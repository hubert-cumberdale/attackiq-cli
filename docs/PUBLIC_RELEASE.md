# Public Release and Enterprise Delivery

This project uses a private source repository as the release authority and publishes a sanitized
source snapshot to a fresh public GitHub repository:

- Private source of truth: current development repository.
- Public mirror target: `hubert-cumberdale/attackiq-cli`.
- First delivery channel: GitHub source only.
- Enterprise package promotion: validated wheel artifacts generated from public release tags.
- Deferred channels: PyPI, automated registry publishing, artifact signing, and registry attestation.
  Artifactory, signing, and attestation evidence can be generated without credentials, but upload,
  signing, and attestation execution remain operator-owned.

## Publication Boundary

- Do not make the long-lived private working repository public in place. Its historical git data is
  outside the public boundary.
- Publish only a no-history source snapshot generated by `scripts/check_public_mirror.py`.
- Do not commit raw tenant responses, browser cookies, bearer tokens, HAR files, generated scenario
  packages, live-smoke output directories, MkDocs `site/`, build output, backup output, or local
  runtime caches.
- Keep release notes focused on product behavior, validation commands, and public-safe operational
  boundaries.
- If the public target already exists and contains commits, stop and review before pushing.

## Snapshot Validation

Before creating any release tag, complete `docs/RELEASE_PREP_EVIDENCE_CHECKLIST.md`. It records
dependency constraints, public safety, secret scan, public mirror dry-run, `pip-audit`, and local
quality-gate evidence. Do not create the tag if any required pre-tag check fails without an
approved exception in the enterprise release record.

Run the standard source/package guard:

```bash
python3 scripts/check_dependency_constraints.py
python3 scripts/check_public_safety.py
python3 scripts/check_secret_scan.py
.venv/bin/pip-audit
.venv/bin/pip-audit -r constraints.txt --no-deps
```

The secret scan uses `security/secret-scan-allowlist.json` and reports only path, line, and rule
label for findings.

For a local development dry run, validate the current working tree without rebuilding a wheel:

```bash
python3 scripts/check_public_mirror.py --allow-dirty --skip-wheel
```

For publication, run from a clean worktree after the release tag exists:

```bash
python3 scripts/check_public_mirror.py --ref vX.Y.Z
```

The strict command:

- exports the tagged source tree to `/tmp/attackiq-cli-public-export-<UTC timestamp>/`
- writes `PUBLICATION_MANIFEST.json`
- scans the exported source and built wheel with the public-safety policy
- initializes a throwaway public-style git repository on `main`
- verifies the snapshot contains exactly one commit

## Public Mirror Push

After the strict validation passes, push the generated export directory to the public target:

```bash
cd /tmp/attackiq-cli-public-export-<UTC timestamp>
git remote add origin https://github.com/hubert-cumberdale/attackiq-cli.git
git push -u origin main
git tag vX.Y.Z
git push origin vX.Y.Z
```

Create the public GitHub release from the public tag. Do not attach wheel, sdist, tenant evidence,
or generated runtime artifacts to the public release unless a later release policy explicitly
approves package attachments.

Use a fine-grained GitHub token or GitHub App installation scoped only to the public mirror
repository with the minimum contents permissions needed to push commits/tags and create the release.
Do not reuse AttackIQ, Artifactory, package-index, or signing credentials for public GitHub work,
and expire or revoke release tokens after the handoff.

## Enterprise Delivery

Enterprise delivery consumes the public source tag and builds credential-free package artifacts:

```bash
python3 scripts/build_enterprise_package.py \
  --source-ref vX.Y.Z \
  --output-dir /tmp/attackiq-cli-enterprise-package-vX.Y.Z
```

The output directory contains:

- `attackiq_cli-<version>-py3-none-any.whl`
- `constraints.txt`
- `SHA256SUMS`
- `ENTERPRISE_PROMOTION_MANIFEST.json`
- `ENTERPRISE_PACKAGE_SBOM.spdx.json`
- `ENTERPRISE_DEPENDENCY_INTEGRITY.json`
- `ENTERPRISE_PACKAGE_PROVENANCE.json`

The package builder:

- clones the public release tag instead of using the private working tree
- runs the public-safety policy against the exact source and built wheel
- writes the checked install constraints record, checksums, promotion manifest metadata, SPDX JSON
  SBOM, dependency integrity record, and package provenance/dependency inventory
- refuses repo-local or non-empty output directories
- does not upload to Artifactory or accept registry credentials

`docs/HASH_PINNED_LOCK_EVALUATION.md` keeps `constraints.txt` plus
`ENTERPRISE_DEPENDENCY_INTEGRITY.json` as the current release standard. Hash-pinned runtime lock
generation is deferred until a future additive prototype proves public-tag generation,
Python-version install compatibility, audit compatibility, and public-safe output boundaries.

Operators can then upload the wheel, `constraints.txt`, `SHA256SUMS`, release notes, promotion
manifest, SBOM, dependency integrity record, and package provenance through their approved
Artifactory or enterprise package workflow.
Keep registry credentials in enterprise secret storage, shell environment, or pip configuration
outside this repository.

Enterprise package upload tokens should be scoped to the target package repository/path only, with
upload and read-back verification permissions but no repository administration, delete, or global
promotion rights. Store token owner, expiry, repository scope, and change-ticket approval in the
enterprise release system, not in this repository.

For Artifactory workflows, generate an internal promotion evidence file after package verification:

```bash
python3 scripts/build_artifactory_promotion_evidence.py \
  /tmp/attackiq-cli-enterprise-package-vX.Y.Z \
  --artifactory-url https://artifactory.example.com/artifactory \
  --repository-path api/pypi/attackiq-cli-local \
  --output /tmp/attackiq-cli-enterprise-package-vX.Y.Z/ARTIFACTORY_PROMOTION_EVIDENCE.json
```

The evidence generator validates the package directory, refuses credential-bearing Artifactory
URLs, records upload filenames/checksums/target paths, and lists post-upload verification commands.
Do not commit evidence files that contain internal repository coordinates.

For signing or registry attestation workflows, generate signing evidence after package and
Artifactory evidence generation:

```bash
python3 scripts/build_signing_attestation_evidence.py \
  /tmp/attackiq-cli-enterprise-package-vX.Y.Z \
  --signing-profile enterprise-release \
  --output /tmp/attackiq-cli-enterprise-package-vX.Y.Z/SIGNING_ATTESTATION_EVIDENCE.json
```

This records signing subjects, expected detached signature files, expected attestation files,
predicate requirements, and standardized external evidence field groups without accepting signing
keys or performing signing.

Signing and attestation verification must use the enterprise-approved trust root. Record the trust
root identifier, policy identifier, verification command, verified subject SHA256 values, and
attestation predicate summary in the enterprise release record; do not commit certificates, private
keys, signing tokens, operator names, change-ticket identifiers, audit-log URLs, or internal
trust-root paths here.

After evidence generation, verify the evidence records offline:

```bash
python3 scripts/verify_enterprise_evidence.py \
  /tmp/attackiq-cli-enterprise-package-vX.Y.Z \
  --require-artifactory \
  --require-signing
```

When direct Artifactory access is unavailable, use
`docs/NO_ARTIFACTORY_RELEASE_EVIDENCE_TEMPLATE.md` to standardize public-safe evidence for package
build, package verification, Artifactory/signing evidence generation, evidence verification, and
local wheelhouse install simulation. The release-audit wrapper evaluation in
`docs/RELEASE_AUDIT_WRAPPER_EVALUATION.md` keeps the template plus individual validation scripts as
the current repository-owned standard and defines the guardrails for any future wrapper.

After downloading the promoted package set, use
`docs/POST_DOWNLOAD_PACKAGE_EVIDENCE_CHECKLIST.md` to cross-check the wheel, constraints, SBOM,
dependency integrity, provenance, signatures, attestations, trust-root verification, and install
smoke evidence before accepting the enterprise handoff.

Verify the generated directory before upload, and repeat the verification after downloading the
same artifact record from Artifactory or another enterprise package repository:

```bash
python3 scripts/verify_enterprise_package.py /tmp/attackiq-cli-enterprise-package-vX.Y.Z --require-constraints
```

Consumer install templates use the `constraints.txt` promoted with the enterprise package or an
approved internal constraints record:

```bash
python -m pip install -c constraints.txt \
  --index-url <artifactory-python-index-url> \
  attackiq-cli==X.Y.Z
```

or, when installing a downloaded wheel from an approved internal artifact record:

```bash
python -m pip install -c constraints.txt attackiq_cli-X.Y.Z-py3-none-any.whl
```

After installation:

- Run `attackiq --version`, `attackiq config validate`, and selected read-only smoke commands.
- Re-enter any tenant credentials from the authoritative secret manager; package artifacts never
  contain tenant secrets.

## Release Checklist

- `pyproject.toml`, `src/attackiq_cli/__init__.py`, `CHANGELOG.md`, and `docs/STATE.md` agree.
- `python3 scripts/check_public_safety.py` passes.
- `python3 scripts/check_public_mirror.py --ref vX.Y.Z` passes from a clean worktree.
- `python3 scripts/build_enterprise_package.py --source-ref vX.Y.Z --output-dir <dir>` passes from
  the public tag when enterprise package promotion is in scope.
- `python3 scripts/verify_enterprise_package.py <dir> --require-constraints` passes before upload and after download.
- `docs/HASH_PINNED_LOCK_EVALUATION.md` has been reviewed when dependency-lock strategy changes
  are in scope.
- `python3 scripts/verify_enterprise_evidence.py <dir> --require-artifactory --require-signing`
  passes after generating Artifactory and signing evidence when both are in scope.
- `docs/NO_ARTIFACTORY_RELEASE_EVIDENCE_TEMPLATE.md` is completed in the approved external release
  record when direct Artifactory access is unavailable.
- The generated public snapshot has one commit and no private git history.
- `.venv/bin/python scripts/quality_gate.py` passes.
- GitHub Actions workflow uses Node 24-compatible official action majors.
- `python3 scripts/check_release_governance.py` passes.
- `pip-audit` passes in the constrained release environment.
- `git diff --check` passes.
- Public GitHub release notes are created from the public-safe changelog entry.
